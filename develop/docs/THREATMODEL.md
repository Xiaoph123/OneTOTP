# OneTOTP 威胁模型（Threat Model）

> **文档性质**：这是项目作者的设计自述，用来明确「防谁、不防谁、凭什么防」。
> **它不是第三方安全审计结论**，也不构成对任何特定部署环境的安全保证。
>
> 适用版本：0.3.0（含 KDF 参数落盘、`zeroize`、数据目录加固）
> 代码位置以仓库当前结构为准；引用到函数名时可直接全文搜索定位。

---

## 1. 系统概览与信任边界

```
┌───────────────────────────── 用户进程（本机） ─────────────────────────────┐
│                                                                            │
│   ① WebView（React 前端）                                                   │
│        │ Tauri IPC（36 个命令，全部为同步 request/response）                 │
│        ▼                                                                   │
│   ② Rust 核心：commands.rs / store.rs / crypto.rs / totp.rs                 │
│        │                                                                   │
│        ├──► ③ Windows Hello 插件（vendored fork：tauri-plugin-biometry）     │
│        │        └── KeyCredentialManager + PasswordVault（Windows Hello）    │
│        │                                                                   │
│        └──► ④ 磁盘：vault.json / lock.json / machine.key / backups/         │
└────────────────────────────────────────────────────────────────────────────┘
```

**信任边界**：

| 边界 | 是否信任 | 说明 |
| --- | --- | --- |
| 前端（WebView） | **不完全信任** | 关键校验一律在 Rust 侧复做：密钥 Base32、位数、周期、算法、分类名长度、颜色格式、设置枚举白名单。前端被绕过也不影响数据正确性 |
| 操作系统 / 内核 | 信任 | 假定本机 OS 未被攻破 |
| Windows Hello / Keystore / Keychain | **有条件信任** | 见 §3-C 的残余风险：系统 API 在部分环境下会「静默成功」 |
| 第三方依赖（crates / npm） | 有条件信任 | 供应链不在本模型防护范围内，需自行审计（见 §4） |
| 磁盘文件 | **不信任** | 一切落盘内容都视为可被读取、复制、篡改 |
| 网络 | 不使用 | 无 HTTP 客户端、无 socket 调用（可脚本核验，见 §5） |

## 2. 受保护资产

按泄露后的危害排序：

| # | 资产 | 存放位置 | 泄露后果 |
| --- | --- | --- | --- |
| A1 | **OTP 密钥（Base32 secret）** | `vault.json` 密文内；解锁后仅在内存 | 可直接生成该账户的验证码 → 等于 2FA 失效 |
| A2 | **锁定口令 / Argon2 派生密钥** | 口令不落盘；密钥仅内存（`Mutex<Option<[u8;32]>>`） | 拿到密钥即可解密 A1 |
| A3 | **账户元数据**（服务名 / 账户标识 / 分类） | 与 A1 同处密文内 | 泄露「你在哪些站点有账户」，可用于钓鱼定向 |
| A4 | **备份串 / 快照** | `backups/*.json`（与主库同密钥）、导出串（独立口令） | 同 A1 |
| A5 | **已复制的验证码** | 系统剪贴板 | 短时有效；默认 30 秒后自动清除 |
| A6 | 锁定凭证 | `lock.json`（salt + HMAC 校验值 + 失败计数） | 不足以解密，但泄露「是否设了口令」与失败历史 |

> **不在内存中的数据**：锁定状态下密钥、载荷、验证码缓存全部清空；关闭到托盘由**原生侧**直接锁定，不依赖前端事件。

## 3. 攻击者模型

### A. 拿到磁盘文件的人（离线攻击）

| 项 | 内容 |
| --- | --- |
| 能力 | 复制走 `vault.json` / `lock.json` / `backups/`，在别的机器上慢慢破解 |
| **是否防护** | ✅ 防护 |
| 机制 | AES-256-GCM（每写一次新 12 字节随机 nonce）；口令经 Argon2id 派生（参数随文件落盘）。`lock.json` 只存 `HMAC-SHA256(密钥, 固定上下文)`，**不能反推出密钥** |
| 残余风险 | 口令强度决定一切。弱口令 + 离线算力仍可能被攻破 → 因此有长度门槛、弱口令黑名单与前端强度提示 |
| 注意 | **无口令模式（`uses_machine_key = true`）不在此列**：密钥是 `machine.key` 里 32 字节明文，与密文同目录，读到目录即可解密。该模式只防「随手翻文件」 |

### B. 物理接触设备、应用处于锁定状态

| 项 | 内容 |
| --- | --- |
| 能力 | 坐在机器前，尝试输入口令 / 触发生物识别 / 重启应用 |
| **是否防护** | ✅ 防护（强度取决于口令） |
| 机制 | 锁定后内存无明文；失败退避 **跨重启生效**（计数写入 `lock.json`，200ms×2ⁿ，封顶 3s）；生物识别每次解锁都必须通过系统验证框 |
| 残余风险 | 有物理接触者可在数小时内反复尝试；退避只是**界面层**成本，真正的防线是 Argon2 计算成本与口令熵 |

### C. 同一登录用户下的恶意进程 / 已解锁的会话

| 项 | 内容 |
| --- | --- |
| 能力 | 读本进程内存、读键盘、读剪贴板、读写应用数据目录、调用同样的系统 API |
| **是否防护** | ❌ **不防**（这是本类工具的通行边界，必须明说） |
| 已有缓解 | 锁定时 `zeroize` 擦除密钥/账户密钥/验证码缓存，缩短明文窗口；剪贴板定时清除；失焦遮挡；离开即锁 |
| 残余风险 | 解锁期间内存中存在 A1 明文，可被同用户进程读取；键盘记录可获取口令 |
| **已知弱点：生物识别凭据** | 存于 PasswordVault 的口令密文，其加密密钥由 Windows Hello 凭证的**公钥**派生，而公钥是公开信息。实测部分环境下 `KeyCredentialManager::OpenAsync` **静默成功、不弹框**。因此：**若有恶意程序以你的身份运行，它理论上可以不经过任何提示就解出该口令**。应用自身已改为每次解密前强制 `UserConsentVerifier` 验证框，但这只能约束**本应用**。彻底解法是「不保存口令、直接用 Hello 派生的密钥加密保险库」，属未来工作 |

### D. 屏幕被看见 / 被记录

| 项 | 内容 |
| --- | --- |
| 能力 | 旁人侧目、截屏工具、录屏、直播、远程桌面 |
| **是否防护** | ✅ 防护（默认全开，可分别关闭） |
| 机制 | ① 窗口内容从系统捕获中剔除（Windows `WDA_EXCLUDEFROMCAPTURE`；Android `FLAG_SECURE`，截屏失败、录屏/投屏/多任务预览黑屏）② 检测到远程桌面会话（`SESSIONNAME` 为 `RDP-*`）时自动隐藏窗口 ③ 窗口失焦时模糊验证码数字 ④ 空闲/失焦自动锁定 |
| 残余风险 | 手机对着屏幕拍照无法防；Windows 上该标志依赖 DWM 捕获管线，某些第三方采集卡/外接录制设备可能绕过 |

### E. 供应链与构建链

| 项 | 内容 |
| --- | --- |
| 能力 | 上游依赖被投毒、构建产物被替换 |
| **是否防护** | ⚠️ 部分防护 |
| 机制 | 依赖数量克制；敏感能力（生物识别、原生扫码）**vendored 到 `plugins/`**，可逐行审计与固定版本；CI 有 secrets 扫描；发布产物由 CI 统一构建 |
| 残余风险 | vendored 插件本身 fork 自上游，其未来安全修复需手动跟进；未做可复现构建（reproducible build） |

### F. 用户自身失误

| 项 | 内容 |
| --- | --- |
| 场景 | 弱口令、把备份串贴在聊天工具里、把 `machine.key` 与 `vault.json` 一起打包外发、忘记口令 |
| 机制 | 弱口令黑名单 + 长度门槛 + 强度提示；备份导出要求**独立口令**（可校验强度）；「忘记口令无法找回」在 UI 与文档中反复明示 |
| 残余风险 | 无法从技术上阻止用户自曝数据 |

## 4. 明确不防（Out of Scope）

以下场景**不在**本模型承诺范围内，读到这里的审计者不应据此判定为缺陷：

1. 操作系统已被攻破（内核级恶意软件、调试器附加到本进程）
2. 同一用户下的恶意程序读取进程内存、键盘记录、截取窗口内容
3. 应用二进制被替换（请核对发布包签名与哈希）
4. 第三方依赖或系统库的上游漏洞
5. 物理胁迫 / 肩窥 / 对屏幕拍照
6. 用户主动导出明文、截图、或把密钥写入聊天记录
7. 时钟被恶意篡改导致 TOTP 偏移（TOTP 依赖本机时间，属协议前提）
8. 多用户共享同一 Windows 账户（PasswordVault 按用户隔离，不按进程隔离）

## 5. 关键安全属性与验证方法

「纯离线」「密钥不出本机」这类承诺应当**可验证**，而不是口号：

| 属性 | 怎么验 |
| --- | --- |
| 不联网 | ① `grep -r "reqwest\|hyper\|ureq\|TcpStream\|UdpSocket" develop/src-tauri/src` 应为空；② 断网运行全部功能；③ 用 Process Monitor 观察进程无网络事件 |
| 落盘无明文 | 解锁前后 `vault.json` 均为 Base64 密文；`strings vault.json` 不含 Base32 密钥 |
| 锁定即清内存 | 单元测试 `close_to_tray_locks_the_vault` 断言密钥/载荷/缓存被清空 |
| 口令校验不可反推 | 单元测试 `verifier_does_not_reveal_the_key`、`verifier_formats_are_not_interchangeable` |
| 旧数据不被锁死 | 单元测试 `legacy_file_without_kdf_field_still_opens`、`legacy_params_match_argon2_defaults` |
| OTP 正确性 | RFC 4226 全 10 条 + RFC 6238 全 6 条官方测试向量 |
| 退避跨重启 | 单元测试 `failed_unlock_count_survives_restart` |
| 数据目录不可被指向远端 | 单元测试 `network_paths_are_recognised`、`pointer_rejects_network_target` |

## 6. 已知限制与加固路线（backlog）

| 优先级 | 项 | 说明 |
| --- | --- | --- |
| 已缓解 | 备份快照与主库共用密钥 | 快照仍需口令才能解开，但**解一次可读全部历史**。真正的危害是「删除了但没撤销」：删除账户时现在会一并清除历史快照中的该密钥（默认开启），换密钥后也会提示旧快照已失效。**剩余风险**：快照本身仍与主库共用密钥——这是刻意的，改成机器密钥加密会让快照失去灾难恢复价值 |
| 部分缓解 | 生物识别凭据的静默解密风险 | 见 §3-C。已做：每次解密前强制系统验证框、界面明示「便捷优先，不额外增加抗本机攻击能力」、提供「移除已保存的凭据」入口。**无法根治**：Windows 现有 API 拿不到「必须 Hello 才能得到」的确定性密钥（签名随机化），除非改用 TPM + NCrypt UI policy |
| 已缓解（可检测性）/ 无法根治 | 数据目录指针无完整性保护 | 指针必须在解锁**之前**读取，而校验所需的密钥只能存在本机 → 同用户攻击者同样能读，故密码学完整性在威胁模型内不可实现。改为「让篡改对人可见」：指针存在但不可用时界面明确告警原因、不再静默回退（否则用户会以为数据丢失）。**剩余风险**：仍无法检测被改写成「另一个合法目录」的情形 |
| 低 | 退避只作用于界面 | 离线破解不受退避约束，只能靠 Argon2 成本与口令熵 |
| 低 | 未做可复现构建 | 建议给发布产物提供签名与哈希清单 |
| 低 | 时钟偏移无提示 | 可加「与上次启动时间比对，异常偏移提示校准」 |

## 7. 变更维护约定

改动下列任一设计时，**必须同步更新本文档**，否则威胁模型会与实际实现脱节：

1. 加密算法、KDF 参数、`vault.json` / `lock.json` 的字段结构
2. 锁定触发条件（失焦 / 空闲 / 关闭到托盘 / 远程会话）
3. 生物识别凭据的存储与验证方式
4. 剪贴板、窗口捕获保护、远程会话检测的行为
5. 任何新增的外部数据入口（导入格式、自定义数据目录、日志）
