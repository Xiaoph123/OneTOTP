## 2. 水印是怎么处理掉的

原图叠着「标小智」「LOGOSC」的斜向灰色水印。没有走手工修图的路线，而是**在分色阶段直接剔除**：

| | 水印 | Logo |
| --- | --- | --- |
| 色彩 | 灰白 | 全彩 |
| 饱和度 | < 10 | > 30 |

以 **饱和度 30** 作为阈值判定"这是墨迹"，水印像素在第一就被整体排除，因此矢量结果里不含任何水印像素，也不会有修图痕迹或残留的灰色斑块。

> 顺带说明：如果水印曾经压在 Logo 上方（而不是在下方），阈值法就会在 Logo 上留下灰色的"洞"。本图的水印在 Logo 之下，所以按上面的做法可以直接、完整地分离。

## 3. 重绘是怎么做的（不是手描，是程序化描摹）

手工照着画一个由多块半透明渐变有机形叠成的标记，既慢又不准。这里走的是一条程序化路径，五步：

| 步骤 | 做法 |
| --- | --- |
| **1. 分色** | 按饱和度分离墨迹与背景（同时剔除水印） |
| **2. 区域分割** | 用**邻域色差**找边界（相邻像素色差 > 16 即视为边缘），非边缘像素做连通域 → 每块 = 一个色区。这个办法能正确切出"半透明叠加"产生的硬边界，同时让区域内部的平滑渐变保持连通 |
| **3. 边缘回收** | 被判定为边缘的像素按颜色归属到最近的邻区，把 1~2px 的边缘带补回去，避免轮廓被削瘦 |
| **4. 轮廓矢量化** | 行进方块法（marching squares）追踪轮廓 → Douglas-Peucker 简化 → 保留拐点的中点二次曲线平滑 |
| **5. 渐变拟合** | 对每个色区，在 36 个方向上投影，取"颜色随位置变化最大"的方向作为渐变轴，沿轴分 6 段采样生成 stop |

结果：标记 **15 个色区**（其中 14 个自动识别为带渐变，1 个平涂）、字标 **9 条轮廓**，整份文件仅 12~19 KB。

### 中间踩到的两个坑（都修掉了）

1. **闭合轮廓被简化算法吃掉**：闭环的首尾是同一个点，Douglas-Peucker 的基准线段长度趋近 0，直接把整条轮廓塌缩成 2 个点 → 输出空路径。修法是先把首尾重复点去掉再做简化。
2. **只检出 1 个拐点时路径退化**：有机形往往只有一个尖角，而"按拐点分段平滑"的逻辑在只有 1 个拐点时会把同一段首尾相接，产出 `M x y L x y Z` 的空路径——大块橙色、紫色区域因此整块消失。修法是拐点少于 2 个时改走整体平滑。

## 6. 直接拿去用

**网页**

```html
<img src="Design/logo/oneTotp-logo.svg" alt="OneTotp" style="height:32px">
```

**换颜色**：字标是单独一条 `<path fill="#F757AF">`，改 `fill` 即可；标记内部的渐变在 `<defs>` 里，每个色区的 `<linearGradient>` 独立，可以单改。

**当应用图标**（`.ico` / `.icns` 已生成好）：

```bash
cp -r develop/src-tauri/icons develop/src-tauri/icons.bak
cp -r Design/logo/tauri/* develop/src-tauri/icons/
```

或者从 SVG 重新生成：

```bash
npx tauri icon Design/logo/oneTotp-icon.svg -o develop/src-tauri/icons
```

## 7. 已知的细节差异

描摹是像素级的忠实还原，不是重新设计，所以：

- 原图本身只有 744 × 159 px，放大到很大尺寸时，曲线的**节点位置**会保留原图抗锯齿边缘的轻微不规则（已在平滑阶段处理过，1:1 与原图基本一致）。
- 若需要"无限放大也完美"的版本，可以在此基础上按拟合出的几何（几个椭圆／叶形）重新落笔成理想曲线；如果你的原始设计稿（AI / Figma / SVG）还在，直接用它更好——**这份交付的意义是在拿不到源文件时，从位图逆推出可用的矢量**。
- 16px 下标记会糊成一团彩色，这是该图形本身的复杂度决定的（它由多块叠加构成）。若需要小尺寸专用图标，建议单独简化一版。
